# 模拟配置顺序与方案依赖

更新：2026-10-13。本说明对应五步模拟界面；科学结论和实际生效值仍以所选冻结源码、算例输入与运行检查为准。

## 先确定什么

先在项目首页选择模型版本，再按以下顺序配置。选择现成方案和过程开关直接保存算例；仅研究中的参数、过程实现、源码或 AI 网络修改需要派生草稿、保存并冻结。已有冻结版本不可原地改写。

| 步骤 | 确定内容 | 为什么在这里 |
| --- | --- | --- |
| 1 范围与网格 | 单点、流域、区域或全球；经纬度、非结构或汇水区网格；边界、分辨率、网格文件 | 决定空间数据、网格内核及后续过程的适用范围 |
| 2 模型结构与方案 | 地表和土壤方案；过程开关及对应设置窗口，包括过程初始化、关联输入和控制选项 | 选择与关联设置集中在一起，避免跨步骤寻找 |
| 3 数据与时段 | 站点、强迫场、地表资料、常规初始条件、时间处理；起止日期 | 保留通用数据设置，过程专用输入在第二步配置 |
| 4 预热与输出 | 模型步长、预热截止、输出频率、重启、诊断和可写输出变量 | 明确实际计算时长及要保留的结果 |
| 5 检查与运行 | 冻结修订、输入、实际内核、运行位置、引擎、线程和阶段 | 核对实际配置与能力，创建/保存之后再启动计算 |

选站默认采用已扫描且匹配该强迫文件的完整覆盖时段；随后可以手动缩短。观测覆盖不自动缩短模拟时段，自定义强迫场不借用另一个文件的日期证明。

## 基础选项不是同一类开关

| 内容 | 所属层 | 控制与约束 |
| --- | --- | --- |
| IGBP / USGS | 内核编译分类 + 建例选择 | IGBP 17 类、USGS 24 类。通过已有建例模式选择对应分类内核；不把只读分类标志写入模型覆盖。已有算例按实际内核或创建记录显示分类 |
| IGBP / USGS / PFT / PC | 算例地表描述方案 | 直接写入算例；`DEF_USE_LCT`、`DEF_USE_PFT`、`DEF_USE_PC` 三项显式互斥，`DEF_SUBGRID_SCHEME` 同属算例。选择不派生模型版本，站点输入和内核能力在后续步骤独立检查 |
| Campbell / vG | 模型运行土壤方案 | `DEF_USE_Campbell_SOIL_MODEL`；vG 还要求 `DEF_USE_VariablySaturatedFlow` 为真。选择 vG 同步启用变饱和流；切回 Campbell 保留其他已配置项 |
| BGC | 模型运行过程 | `DEF_USE_BGC`，要求 PFT 或 PC。显式开启前先确定结构；已开启时不能直接切 LCT |
| 河湖汇流 | 编译能力与模型运行过程 | `DEF_USE_GridRiverLakeFlow`；需要所选内核的网格河湖能力和适合的空间网格。汇水区侧向流不是同一个开关 |
| CROP | 编译能力及作物输入 | 实际内核需要 CROP 能力，并满足 BGC 及相关输入要求。页面显示候选内核能力与算例输入标记，最终核对由后端完成 |
| 城市 | 模型运行过程与城市输入 | `DEF_URBAN_RUN`。需要真实城市输入；不能仅依据开关声称数据完整 |
| 示踪与 CH4 | 模型运行过程及过程资产 | `DEF_USE_TRACER`、示踪名称/类型和过程文件。CH4 是示踪物族，要求 PFT/PC、BGC、vG，并与城市过程不兼容；完整族及资产校验保留在后端 |
| `DEF_SUBGRID_SCHEME` | 已读入但未参与计算的参考项 | 不再作为结构选择依据，也不提供可编辑入口；实际结构由上述三个逻辑开关确定 |

页面使用 IGBP、USGS、PFT、PC 四个并列卡片，直接更新算例的完整互斥开关，不进入版本编辑或冻结流程。PFT/PC 保留算例的 IGBP/USGS 数据来源。模型版本只管过程实现、参数、源码和 AI 网络；BGC/CROP 等前提从算例方案读取，冲突明确提示，不自动关闭物理过程。已有算例选择方案只保存配置，不表示已重建站点数据；第三步仍核对真实输入和内核兼容性。

安装了某分类的内核只说明存在候选能力，不能证明它适配所选源码、参数或输入。不同源码版本的未覆盖默认值不得用当前应用目录默认值替代。没有显式覆盖时页面显示“实际值待检查”。

## 过程方案与参数怎么找

模拟配置页列出后端可写的算例字段，按九类展开：次网格与植被、土壤、水热、生态与生地化、示踪、城市、河道与水库、数据同化、其他模型选项。原目录中存在的方案仍可查看，不用一组精简卡片替代完整科学配置。

完整参数目录直接复用 `parameter_catalog`，可按名称和作用域筛选，展示标签、原字段、单位、启用条件、存储/编辑范围、目录参考默认值和源码位置。版本修改页仅允许后端真正支持的模型字段与资产覆盖。

| 参数作用域 | 配置原则 |
| --- | --- |
| 算例标量 | 地点、时段、路径、输出在对应步骤改；属于模型的标量可以进入版本覆盖 |
| 地类 | 绑定 IGBP/USGS 分类及类别编号，单点标量覆盖需要单点内核；不假装支持区域多类覆盖 |
| PFT | 先显式选择 PFT 结构，再应用合法编号的参数 |
| PC-PFT | 先显式选择 PC 结构，再应用合法编号的参数 |
| 过程文件 | 使用既有过程文件/资产入口并记录哈希；名称、类型及输入校验不能省略 |
| 只读、内部或尚无写入钩子的字段 | 展示来源和限制，不包装为已经能写入并生效的控件 |

版本含 PFT/PC 参数时，兼容性检查读取算例的三个显式互斥开关；算例缺失开关或方案不匹配即拒绝。历史版本的算例控制字段保留存储字节及指纹，但不再覆盖算例；派生草稿不继承这些字段。

先确定结构，再确定依赖它的方案和参数。参数压边界、缺观测或指标偏差不能自动证明结构有问题；需要单独的内置分析与验证实验。

## 旧版条件选项的对应入口

新版第二步使用只读条件查询展示算例选项。用户成功开启 BGC、河湖汇流、城市、作物或示踪等选项后，打开对应设置窗口；已开启项旁的“设置”可再次进入，首次加载不会自动弹窗。窗口中的子配置先暂存，保存时一次提交，取消或关闭丢弃子配置草稿而保留已经开启的父选项。关闭父开关保留已保存子项。实际参数、过程文件内容和索引参数仍在研究中编辑，保存为新版本。

| 父条件 | 第二步选项／研究中的参数 | 对应设置窗口与进一步条件 |
| --- | --- | --- |
| BGC + PFT/PC | LAI 反馈、无氮胁迫、SASU、诊断矩阵、PN、硝化反硝化、火过程 | BGC 初始化与氮沉降；开启 CN 初始化后配置对应文件 |
| BGC + 作物能力与输入 | 施肥、肥源、固氮、灌溉；PFT/PC 参数表的作物参数 | 仍须核对实际 CROP 内核和站点农田输入；非 CROP 内核不能使用 16–78 的索引覆盖 |
| 河湖汇流 | 水库方法、估算河深、汇流子步长、漫滩蓄水修正 | 河网、水库输入；漫滩回馈和最大入渗还受 TOPMODEL、LCT、VSF、LULCC、城市等条件限制 |
| TRACER | 按行对应的名称、类型、分子质量、参考比率、初始 δ、衰减率和过程文件；同位素分馏等子项 | 示踪初始化和驱动数据；类型、土壤方案、网格及实际强迫决定进一步可用性 |
| CH4 + BGC + PFT/PC + vG | 已导入 CH4 过程文件中的淹没方案 | 城市过程不兼容；satellite 使用 GIEMS；routing/hybrid 还需空间范围与河湖汇流。CH4 参数文件与算例动态湿地开关在运行检查中核对 |
| 同位素 | 分馏、动力学、土壤扩散和其他已编目选项，以及对应过程参数文件 | 空间分馏还需要适配的主强迫与同位素强迫；不凭开关声称数据已齐全 |
| Cl 溶质 | 对应过程文件的初始浓度、降水浓度和其他已编目参数 | 通过真实过程资产编辑，不写成主文件里的伪字段 |
| 颗粒／泥沙 | 类型选择 `particle`，对应过程资产 | 需要空间网格河湖能力及河湖汇流；不增加不存在的通用 BGC 依赖 |

没有独立的“BGC + 河湖汇流”万能分组；具体组合出现在 CH4 的 routing/hybrid 等实际过程条件中。过程专用字段集中在第二步对应设置窗口，第三步不再重复展示。窗口保留原有专用示踪编辑器和条件查询；修改候选配置后重新核对，最终保存和运行仍由后端校验。

过程文件读取所选修订或草稿中按哈希验证的真实资产，并合并当前覆盖。没有资产时需先导入，不把当前源码模板自动当成旧修订的资产。过程数组逐元素保持类型；恢复资产原值只移除本文件的覆盖，活动 CH4 的湿地要求在算例兼容性检查中核对。

PFT/PC 索引参数单独展开，明确选择作用域和类型，再查询参数及不可用原因；不默认猜测站点拥有类型 0。示踪定义成组应用，数值列须为有限数值，允许整列留空；文件映射按名称或位置读取，支持旧版分隔形式，未编辑文件关联时保留原字符串。

查询绑定冻结修订，或草稿 ID、generation 与覆盖内容；切换版本、输入或内核后丢弃旧响应。只有显式已知的父开关和实际内核能力能确认禁用。未读取所选源码默认值的条件标为“待核对”，目录默认值始终仅供参考。

## 数据变更与兼容性

模型调整后返回第二步，保留待建算例的分类、日期和路径，再进入第三步核对站点兼容性。模型预览保留源算例的分类及来源、作物输入和空间范围，采用算例选定的地表方案；PFT/PC 不覆盖或猜测 USGS 身份。

覆盖物化先应用标量，再应用有作用域的参数，参数记录的排列不改变兼容性。运行结构在模型覆盖、最终物化文档和实际内核门槛分别检查。服务器提交与服务端接续也核对最终选择的远程内核，不以本地候选内核代替。

## 第二步内部的顺序卡片与完整旧链核对

第二步以同款框卡依次配置：**植被 → 土壤水力 → 变饱和流 → 河湖汇流 → 区域单元汇流 → 土地覆盖变化 → BGC → 城市 → 作物 → 示踪**。基础卡不再只是文本说明；已知缺少前提时禁用激活选择并就近给出原因，未确认的冻结默认和环境标为待核对。这一组现成方案与开关直接保存算例，模型修订保持不变。改变上游保留下游参数，有明确冲突时先处理冲突。

| 旧链入口 | 本轮卡片或后续实际入口 | 需要确认的前提与输入 |
| --- | --- | --- |
| 土壤水力 | Campbell/vG；变饱和流开关；水热组产流方案卡 | vG 同步启用变饱和流；已启用示踪时不能直接改 Campbell |
| 河湖 | 格点河湖卡；河道/水库/漫滩后续字段 | 需要空间范围与实际 GridRiverLakeFlow 能力；Catchment 侧向流不等同于该选项；漫滩反馈仍逐条核对 LCT/TOPMODEL/蓄量修正/非城市非LULCC等条件 |
| 区域单元汇流 | 河湖后的独立开关卡 | 开启需空间网格河湖及非LULCC；关闭入口保持可用，便于先满足LULCC前提 |
| LULCC | 基础土地变化卡与原次网格后续字段 | 非单点、非USGS、非Catchment、非BGC；区域单元汇流和同位素冲突；数据年份在数据与运行检查中核对 |
| BGC | 基础BGC卡和关联设置窗口；氮限制、LAI反馈、SASU、诊断矩阵、PN、硝化、火过程、初始化与氮沉降 | 先明确PFT/PC；单点城市不兼容；通用Runtime目录留在数据步骤 |
| CROP | 作物卡和设置窗口中的种植日、灌溉、施肥、肥源及固氮；CFT参数在研究中 | CROP是实际候选编译能力，不能写伪DEF_USE_CROP；开启沿用标准建例默认值（单点种植日120、空间0），已有显式值保留；单点0–366，空间0；还需真实作物站点/输入 |
| URBAN | 城市卡和设置窗口中的城市控制、关联数据和LCZ/NCAR分类 | 非Catchment、非TRACER；单点BGC不兼容；NCAR需要真实urban属性文件，不以分类目录代替文件检查 |
| TRACER | 父卡；水同位素/CH4/Cl/泥沙四家族卡；对齐定义表 | vG、非城市、非Catchment；新家族只暂存名称/类型，保留原行和自定义类型；完善数值列和关联文件后显式应用，不填科研测试默认 |
| 水同位素 | 分馏选择卡、含水层混合水量、动力学/扩散、H2_18O/HDO过程文件 | 不能LULCC；分馏需空间及真实IsoGSM主/示踪强迫；混合水量需用户提供正值，不预填1000mm |
| CH4 | 活动CH4文件的五种淹没选择卡及其他真实过程条目 | PFT/PC+BGC+vG；routing/hybrid还需空间格点河湖；satellite需GIEMS；活动资产与算例动态湿地开关须满足一致的运行约束 |
| Cl | Cl定义、真实过程文件中的初始/降水浓度 | 浓度由用户填写并按目录数值约束验证，不填旧测试1e-5/2e-6 |
| 泥沙 | SEDIMENT/SED家族卡和真实泥沙过程参数 | 空间范围、格点河湖能力及运行开关 |
| 气孔 | Ball–Berry/Medlyn/WUE三卡 | 双开关原子互斥，缺失/冲突值待确认；直接保存算例 |
| 初始化和强迫 | 第三步保留通用输入；CN、示踪、城市及河湖流专用输入进入第二步对应设置 | Soil/Snow/CN/水位/Ozone/GIEMS/降尺度等文件依旧按实际字段状态与路径核查；取消窗口不捏造已准备输入 |
| 输出与调试 | 第四步已有历史变量、范围检查、日志等字段 | hist_vars仍绑定真实算例与内核，区分writable/settable/unknown；不复制旧SrfdataDiag恒禁用缺陷 |

完整盘点来源是旧 `gui/dist/app/domain.js` 的定义、pages、全部block/transition和wizardFields，及 `params.js` 的field_states_batch/PFT/过程文件/文件联动、`kernel.js`、`runner.js`、`histvars.js`。旧自动清除下游、测试值及静态维护文案不作为新科学默认。当前前提以 `config.rs`、`model_configuration.rs`、所选内核和绑定资产为准；`model_configuration.allowed_values`是完整schema候选，不表示全部组合已通过运行验收。


## 四种方案的直接选择入口

新建模拟或已有算例点击 IGBP／USGS／PFT／PC 后，直接更新算例配置，保持所选模型修订不变。没有“应用方案”或为方案派生、保存、冻结模型版本的步骤。模型编辑页的“← 返回模拟配置”位于顶部，仅存在未保存模型修改时禁止返回；已保存草稿可留在版本库中继续编辑，返回后仍使用原修订。站点真实组成及输入在下一步检查。


## 统一边界

没有修改参数或过程实现的配置均属于算例，包括土壤水力、气孔、BGC、汇流、城市、作物种植设置和示踪定义。参数目录中的字段并非全部属于模型；示踪 CSV 定义和种植日属于算例，有限数值检查仍保留。实际率定系数、地类/PFT 参数和过程文件参数属于研究版本。模拟页面的过程文件参数仅查看，调整进入研究。清除旧示踪文件关联保存显式空关联，避免历史版本再次恢复旧引用。
