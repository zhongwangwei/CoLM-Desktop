# GUI audit — 2026-09-08

Scope: `gui/` frontend ES modules, Tauri backend, GUI tests, and this report. Reviewed against `docs/code-review-2026-08-26.md` to avoid repeating prior findings. This pass focused on confirmed, reproducible bugs and kept fixes minimal; no dependencies were added and no visual design/style changes were made.

## Confirmed findings and fixes

| 文件/模块 | 严重度 | 复现/证据 | 修复 | 测试 | 风险/剩余 |
|---|---:|---|---|---|---|
| `gui/dist/app/sites.js`, `gui/dist/app/params.js`, `gui/dist/app/timing.js`, `gui/dist/app/histvars.js` — case selection / parameter render async state | High | Fast A→B selection can let stale A responses from `read_text`, `unknown_fields`, `read_case`, `read_timing`, `hist_vars`, `land_cover_contexts`, `varying_fields`, `field_states_batch`, expert process files, or PFT state write into the currently selected B UI/state. A trailing guard in `selectCase()` cannot undo writes made inside `renderFields()`. | Added selection token in `selectCase()`; added internal `renderFieldsGeneration` so every caller of `renderFields()` is last-request-wins by default; guarded all cross-`await` state/DOM writes; passed the same guard into `renderTiming()` and `renderHistVars()`; guarded expert process/PFT subrenders. | `gui/tests/params-race.mjs` executable out-of-order regressions for stale case text, default `renderFields()` stale `read_timing`, and stale `hist_vars`; `node gui/tests/params-race.mjs`; full `gui/tests/*.mjs`. | Does not cancel old IPC requests; it ignores late responses. That preserves existing IPC contract and avoids backend churn. |
| `gui/dist/app/sites.js` — site scan after path changes while scan button disabled | Medium | `scheduleSiteScan()` previously clicked a disabled scan button. If `Sitedata`/forcing path changed while an old `scan_sites` was in flight, the queued click was dropped and stale results could populate the new path. | Captured `sitedir`/`forcingdir` for each scan; late responses whose inputs no longer match are dropped; a pending rescan is scheduled after the old scan re-enables the button. | Static regression in `gui/tests/sitepaths.mjs`; `node gui/tests/sitepaths.mjs`; full `gui/tests/*.mjs`. | Still debounce-only, not request cancellation; adequate because stale results are discarded and latest inputs rescan. |
| `gui/src-tauri/src/config.rs`, `gui/src-tauri/src/project.rs` — `DEF_CASE_NAME` path / history escape | High | `set_field` uses schema lookup case-insensitively, so checking only requested path spelling could miss `def_case_name`; `list_cases()`/`history_of()` used namelist case name to build `out/<name>/history`, so path-like names could escape or mark outside history as valid. | Reused shared `colm_case::validate_case_name()` via GUI helper; `typed()` validates schema field name with `eq_ignore_ascii_case`; `list_cases()` falls back to directory basename when namelist case name is invalid; `history_of()` refuses invalid names before joining paths. | `case_name_must_not_be_a_path`; `a_path_like_case_name_cannot_escape_history_lookup`; full `cargo test --manifest-path gui/src-tauri/Cargo.toml --lib`. | Non-GUI case-name/path callers were not changed in this lane. |
| `gui/src-tauri/src/config.rs` — process namelist group comments | Medium | Manual group extraction treated `&nl_colm_methane_parameter ! note` as a distinct group, hiding insertable defaults and misclassifying process parameter files once namelist parser preserves/comment-roundtrips group lines. | Group extraction now strips trailing `!` comment before trimming and removing leading `&`. | `process_group_comments_do_not_hide_insertable_defaults`; full GUI lib tests. | Relies on shared namelist parser preserving group line text; compatible with `.trim()` callers. |
| `crates/colm-case/src/build.rs`, `crates/colm-cli/src/main.rs`, `gui/src-tauri/src/config.rs`, `gui/dist/app/timing.js`, `gui/tests/results.mjs` — spinup invalid date / JS 32-bit truncation | High | `2008-02-29 + 1` produced invalid `2009-02-29`; huge `u32` years could be truncated by caller-side `as i32`; `spinup_repeat` above Fortran INTEGER range and invalid cutoff seconds could be serialized by callers; frontend basic spinup used `+value | 0`, silently truncating to signed 32-bit before backend validation. | Moved cutoff/year/date/repeat/second validation into shared `colm_case::spinup_cutoff()` / `spinup_fields()` `Result` boundary; `fields()` now returns `Result` so case generation callers propagate invalid spinup instead of panicking or wrapping a second API; `spatial_fields()` remains `Vec` because it always calls `Spinup::OFF`; GUI `set_spinup` uses shared cutoff/field generation and removed its duplicate civil-date helper; frontend basic spinup uses `Number()` + `Number.isSafeInteger()`. | `spinup_generation_rejects_nonexistent_cutoff_dates`; `spinup_generation_rejects_years_outside_i32`; `spinup_generation_rejects_repeat_outside_fortran_integer`; `spinup_generation_rejects_cutoff_seconds_outside_a_day`; `cli_spinup_window_check_*`; GUI `spinup_rejects_*`; `gui/tests/results.mjs`. Behavior red was the old algorithm `2008-02-29 + 1 -> 2009-02-29`, caller-side huge-year truncation, repeat values beyond Fortran INTEGER, and GUI/backend cutoff seconds cast/serialization; compile red only identified every caller needing `Result` propagation. | Shared boundary now protects direct generator callers and GUI/CLI caller paths; oracle fixtures are known-valid and explicitly `expect` the `fields()` result in tests. In this environment `PLUMBER2_ROOT` was unset, so oracle generated/forcing-convert test entrances compiled and their available branches passed, but real PLUMBER2/golden comparison branches were skipped. |
