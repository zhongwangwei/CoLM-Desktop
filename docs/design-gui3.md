# GUI 工作流重划设计（里程碑 14）

> 这是**设计**，不是实施计划。实施计划另出 `docs/plan-gui3.md`。

**目标：** 把现在这条「五步平铺、进门即工作台」的流程，改成
「先分流域类型 → 六步」的形状，并把参数页的常规/专家开关腾空。

**改动边界：** 几乎全在 `gui/dist/`（前端）与 `gui/dist/index.html`。
**后端 Rust 不动** —— 不新增、不删改任何 Tauri 命令，429 个 Tauri 依赖不用重编。

把这 6 个整合进各分节之后，专家模式就是一个空壳，等后续安排。

## 1. 启动弹框：先分流域类型

进门第一件事是选**这次要跑什么**，而不是直接落在工作台上。

```
┌───────────────────────────────────────────────────────┐
│                  这次要跑什么？                        │
│                                                       │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  │
│  │  ● 站点     │  │  ○ 区域     │  │  ○ 全球     │  │
│  │             │  │             │  │             │  │
│  │ PLUMBER2 /  │  │  暂不支持   │  │  暂不支持   │  │
│  │ Urban-      │  │   （灰）    │  │   （灰）    │  │
│  │ PLUMBER 单点│  │             │  │             │  │
│  └─────────────┘  └─────────────┘  └─────────────┘  │
└───────────────────────────────────────────────────────┘
```

**三档而不是两档。** 区域与全球是两种不同的东西（有限范围网格 vs 全球网格），
它们各自要的前处理、地表数据与并行设置都不一样。现在就把三档摆出来，
将来任何一档落地时不用再改这一层，且用户一眼看得到路线图。

- 新模块 `gui/dist/app/domain.js`，职责单一：显示门、记录选择
- `state.domain = null | 'site' | 'region' | 'global'`，现阶段只有 `'site'` 可点
- **每次启动都弹，不记忆。** 选完 → `state.domain = 'site'` → 门隐藏 → `go('prep')`
- **后台初始化照常跑**（`describe_fields`、`refreshKernels`、recent 恢复），
  门只是视觉遮挡。用户点完站点时界面已经就绪，`backend_ready` 那条面包屑不受影响
- 依赖方向 `domain.js → state/ui/shell`，只被 `main.js` import。
  **不被任何业务模块 import** —— `check-gui` 禁止模块成环，而 `sites ↔ results` 有前科

**被否决的方案：** 只在第一次弹、之后记住。
理由是这个门在区域与全球落地后是真正的分流点，不是一次性的欢迎页；
每次确认一遍比藏进一个「切换模式」的下拉框更诚实。

## 2. 六步：内核在前，站点在后

**顺序由依赖链定，不由习惯定。**

```
内核（无依赖）  →  站点（要先知道内核）  →  时间与预热（要先有 case.nml）
```

| 步 | id | 内容 | 进入条件 |
|---|---|---|---|
| ① 前处理 | `prep` | 不动（占位页） | 无 |
| ② **基本设定** | `basic` | **内核**：下拉 + 宏组合说明<br>**算例放哪**：`root` 目录<br>**城市栅格**：内核是 `urban` 时才出现的 `rawdata` / `runtime` | 无 |
| ③ 站点 | `sites` | 站点目录 · 扫描 · 用自带示例 · 站点列表 · 全选/全不选 · **建算例** | 选了内核 |
| ④ 参数 | `params` | **时间与预热** · 13 个分节的字段表 + 过滤框 | 已建算例 |
| ⑤ 运行 | `run` | 输出频率/目录/重启 · history 变量勾选 · 跑哪些 · 开始运行 | 已建算例 |
| ⑥ 结果 | `result` | 曲线 + 与观测比对 | 已建算例 |

### 2.0 为什么内核必须排在站点前面

**内核决定了哪些站点跑得了。** 城市站（Urban-PLUMBER）必须走 `URBANON` 编进去的
内核，而且必须给全球栅格目录 —— 土壤剖面、湖深、土壤反照率与 LCZ 分类
都只能从那里取，站点文件里没有。`default` 内核跑不了城市站，要的数据和路径
也完全不同。

原来的顺序（先选站点、再选内核）把这条依赖倒过来了：人先挑了二十个城市站，
到了下一步才发现手上的内核是 `default`，全部白挑。

**时间与预热跟着 `case.nml` 走。** 它读的是 `DEF_simulation_time%*`，
而那份文件是建算例产出的 —— 建算例又要先有站点。所以它落在参数页，
和它实际写进去的那份 namelist 在同一页。

### 2.0.1 站点页要说出「这个站点配不配得上当前内核」

**标出来，不要过滤掉。** 内核是 `urban` 时把非城市站藏起来，或者反过来，
都会让人以为「扫出来就这么多」——而这个程序自己立过规矩：
静默跳过与静默失败在界面上长得一样。

做法是在站点行的标签里多一条，并在页顶给一句当前内核的上下文：

| 当前内核 | 城市站 | 非城市站 |
|---|---|---|
| `urban` | 正常 | 标「要 default 内核」 |
| `default` / `bgc` | 标「要 urban 内核」 | 正常 |

判据用 `scan` 已经返回的 `urban: bool` 与内核 `manifest.json` 里的
`generator_args` 是否含 `URBANON`，**不新增后端命令**。

### 2.1 `#cases` 一个元素进不了两页

第 3 步（站点）建完算例要看见「建出来没有」，第 5 步（运行）要「跑哪些」，
现在是同一个 `#cases`。

**方案：`renderCases(box)` 参数化，两页各一个容器**
（`#cases-built` / `#cases-run`），共享同一份 `state.cases` 与 `state.pickedCases`。
勾选语义统一为「批量目标」：第 3 步勾了批量建，第 5 步勾了批量跑，**勾选状态贯通**。

**被否决的方案：** 只在一页保留列表、另一页显示摘要。
两处都需要看到「哪些算例存在、现在处在哪一段」，而一个摘要行答不了
「AU-DaS 到底建出来没有」。

### 2.2 多站点是一等公民，不是特例

**配的可能是二十个站点，不是一个。** 第 3 步勾中任意多个站点，
一次建出二十个算例，后面三步全部对整批生效：

| 在哪一步 | 对整批怎么生效 |
|---|---|
| ② 内核 | 一个内核对整批生效 —— 编译期宏本来就是全局的，也正因如此它排在最前 |
| ③ 建算例 | `ensureCases()` 串行为每个站点建一个算例目录（**串行不并发** —— 每次都要读站点文件与强迫场并写出 `site.nc`，瓶颈在磁盘） |
| ④ 时间与预热 | `read_timing({dirs})` 收整批，取值不一致时显示「各算例从自己的预热结束处开始」 |
| ④ 字段表 | `set_field_batch` 写整批；`varying_fields` 标出这批里取值不同的字段 |

后端与状态层**本来就是批量的**。要补的是界面：

**界面必须随时说出现在在配几个。**

- 左栏「已选站点」批量时显示 `AT-Neu 等 20 个`，不是只显示一个名字
- 顶栏算例名批量时显示 `20 个算例`
- 勾选动作要**立刻**刷新左栏 —— `renderSites()` 与勾选框的 `onchange` 都得
  带上 `renderSteps()`，否则勾了二十个左栏还写着上一次的数
- 参数页已有的 `renderScope()` 横幅（「下面的改动会写进 N 个算例」）保持不动
- 步骤门槛与按钮文案一律说「站点」，不说「一个站点」

**为什么这条要单独写出来：** 勾了 20 个站点却只显示一个名字，界面看起来像在
配一个，而改一个字段会写进 20 份 `case.nml` —— 那是**看不出异常的**破坏。

### 2.3 出口按钮的归属

站点页现在带 `data-own-foot`，`renderNextButtons()` 因此跳过它，
出口由 `renderDataFoot()` 自己渲染（那个按钮会先建算例再翻页）。

改造后：

- **站点页去掉 `data-own-foot`**，出口交回通用的「下一步：参数 →」
- 「确定：建算例」是站点页里的**动作按钮**，不是页面出口
- `renderDataFoot()` 更名 `renderMakeCase()`，`#datafoot` 更名 `#makecase` ——
  step id 已经从 `data` 改成 `sites`，留着 `data` 前缀会让人去找一个
  不存在的步骤

**算例目录在第 2 步、建算例在第 3 步**，这正好修掉原来那条自己吐槽的注释：
出口摆在设定算例目录之前，等于让人先按确定再想产物放哪。现在先设目录、
后建算例，顺序是对的。

**两个长得差不多、行为不同的按钮不能摆在一起** —— 这是 `shell.js` 里
`data-own-foot` 那条注释立下的规矩，改造后仍然成立：页面出口只有一种。

## 2.4 `default` 更名 `default`

`default` 这个名字说的是它编进了什么（水热过程），但它实际的角色是
**默认预设** —— 三个里最常用、文档里到处拿它举例的那个。改名 `default`。

范围：**除 `docs/plan-m*.md` 与 `docs/plan-gui[12].md` 之外全改**。那些是历史
记录，改了会让当时的实测输出对不上。要改的：

| 位置 | 改什么 |
|---|---|
| `oracle/scripts/build_kernel.sh` | `case` 分支的 preset 名 |
| `kernels/default/` | 目录名 + `manifest.json` 的 `preset` 字段 |
| `crates/colm-kernel/`、`crates/colm-hist/`、`crates/colm-cli/` | 源码与测试里的字面量 |
| `oracle/tests/`、`oracle/src/bin/golden_run.rs` | 同上 |
| `oracle/golden/kernel-manifest.json` | **回归黄金基准** —— 改完必须重跑一次黄金比对 |
| `.github/workflows/release.yml`、`windows-kernel.yml` | `for p in default bgc urban` 与路径 |
| `README.md` | 预设表与正文 |

**黄金文件那一条是这次改名唯一有风险的地方。** 它是回归基准，改它等于
改判据；所以改完要跑一次真实的黄金比对，确认 `identical: 129 variables`
仍然成立 —— 只改名字不该动到任何一个字节的输出。

## 3. 参数页：derived 整合进各分节，专家模式腾空

- 删掉 `.filter(e => state.expert || !e.derived)` 这层过滤
- 那 6 个 derived 按自己的 `section` 归进对应分节，
  **排在该分节可编辑字段之后**，值列仍是灰色的「（派生值，改不了）」
- 分节标题的计数把 derived 算进去
- 常规/专家开关、`state.expert`、`body.expert` **全部保留不动** ——
  那是将来挂 CSS 与额外选项的钩子，不能因为这轮空着就拆掉
- 专家模式这轮没有额外内容 → 切过去时给一句「专家选项还在规划中」的占位。
  **不做成点了没反应的按钮** —— 静默无反应与静默失败在界面上长得一样

**为什么可编辑在前、只读在后：** 只读行混在中间会打断编辑节奏。
按 `field_section()` 实际推导，这 6 个的分布是：

| 分节 | derived 字段 | 判据 | 渲染到哪 |
|---|---|---|---|
| 文件与目录 | `DEF_dir_landdata` | `starts_with("DEF_DIR")` | 参数页字段表 |
| 地表数据 | `DEF_USE_USGS` `DEF_USE_IGBP` | 名单命中 | 参数页字段表 |
| 示踪剂 | `DEF_wetland_finundation_scheme` | 命中 `WETLAND_FINUNDATION` | 参数页字段表（TRACEROFF 时被内核过滤掉） |
| 输出与重启 | `DEF_dir_restart` `DEF_dir_history` | **显式列举** `n == "DEF_DIR_RESTART"` / `"DEF_DIR_HISTORY"` | 运行页的输出卡片 |

**这两个是坑，值得写下来。** 光看前缀会以为 `DEF_dir_restart` 归「文件与目录」
（`DEF_DIR` 开头），实际不是 —— `config.rs` 第 28–29 行**显式列举**了这两个
名字，而那个 `if` 早于 `DEF_DIR` 前缀规则。判归属要读到显式列举那一段，
不能只看前缀。

后果是它们落在 `renderFields()` 的 `outputFields` 分支（运行页）而不是
`PARAM_SECTIONS` 循环（参数页），所以**两个分支都要排序**，只改一个会让
运行页的派生项混在中间。

## 5. 错误处理

- **门不拦后台初始化的错误。** `list_kernels` 失败、示例数据装不上，
  照常落状态栏，用户选完站点就看得见 —— 把错误藏在门后面等于延迟暴露
- 步骤灰着时沿用现有 `need()` 机制说出原因，不做成纯灰的死按钮
- 区域与全球那两张卡片是 `disabled` 而不是「点了报错」——
  一个能点但必然失败的入口比一个灰着的更糟

---

## 6. 不做什么

- **不引入前端框架、构建工具或 npm 依赖。** 既有约束，见 `design.md` §4.2
- **不动后端。** 这轮不新增、不删改任何 Tauri 命令
- **不实现区域与全球的步骤链。** 只把入口摆出来
- **不按内核过滤站点列表。** 只在行上标出「要 urban 内核」/「要 default 内核」——
  藏起来会让人以为「扫出来就这么多」
- **不改 `docs/plan-m*.md` 与 `docs/plan-gui[12].md` 里的 `default`。**
  那些是历史记录，改了会让当时的实测输出对不上
- **不给专家模式编内容。** 腾空等后续安排
- **不动第 ⑥ 步结果页。** 它现在的形状是对的

## 7. 验证

| 手段 | 覆盖 |
|---|---|
| `cargo run -p xtask -- check-gui` | 新模块不成环、invoke 参数名对得上、import 解析得了 |
| `node --check` 每个改动的 `.js` | 语法 |
| `cargo test`（GUI 后端 43 tests） | 这轮不动 Rust，回归保险 |
| 跑起来用辅助功能树逐条读 | 门出现/消失、步骤条 6 项且顺序是 前处理/基本设定/站点/参数/运行/结果、内核卡片在第 2 步、建算例在第 3 步、时间卡片在第 4 步、两个算例列表勾选贯通 |
| playwright + 静态服务器读 DOM | 纯前端改动（门、步骤条、文案）—— 比真窗口快得多，但**浏览器里没有 IPC 后端**，`boot()` 整个不执行，凡走后端的一律验不了 |
| `cargo run -p oracle --bin golden-compare` | **改名之后**输出仍是 `identical: 129 variables` —— 只改名字不该动到任何一个字节 |

**最后一条不能省。** 这个项目已经吃过一次亏：进度条建在一个永远不会到达的
输入上，静态检查全绿，而它从来不动（README「进度条曾经建在一个永远不会到达的
输入上」）。DOM 结构改动尤其如此 —— `check-gui` 验的是「发出去的事件都有人听」，
验不了「这一页上真的有东西」。
