# CoLM Desktop 结果分析工作台实施计划

**日期**：2026-08-22  
**状态**：已实施并进入最终验证  
**范围**：单点及多站点结果浏览、评估、诊断与导出

## 1. 目标

把现有依赖单个 `state.selected` 的“曲线 + 评估”长页面，替换为独立的结果分析工作台。结果上下文不得改变参数编辑上下文；一个站点失败、缺观测或缺变量不得阻断其他站点。

左侧结果工作流采用七个可折叠分栏：

1. 分析总览
2. 数据浏览
3. 时间序列
4. 模型评估
5. 多站点比较
6. 过程诊断
7. 报告与导出

## 2. 状态边界

- 结果范围只来自本次创建的算例 `currentCases()`，不扫描算例根目录中的旧算例。
- `resultCaseDir` 是结果页当前站点；不复用参数页的 `state.selected`。
- 多站点结果默认包含本次所有已产生 history 的算例，不受运行页残留勾选影响。
- 算例与源站点通过 `site_file -> case dir` 映射关联，改名后的算例仍能找到观测。
- 每个站点独立记录观测覆盖路径、指标、错误和数据质量状态。

## 3. 性能约束

- 总览只读取轻量 history 目录索引；序列、指标和诊断按需加载。
- 图表请求默认限制为不超过 2400 个显示点，降采样必须保留每个桶的极值。
- 序列缓存为有限 LRU；指标缓存键包含算例、观测、丢弃条数和订正选项。
- 算例重新运行成功后清除该算例全部结果缓存。
- 多站点评估使用有上限的并发池；默认 `min(4, logical CPUs)`，单站点失败作为结果返回。
- 离开分栏时销毁不再连接 DOM 的图表，过期异步响应不得覆盖当前站点。

## 4. 数据与展示

- history catalog 返回文件数、时间范围、步数、变量、单位、维度和可绘制类型。
- 标量时间序列走 uPlot；剖面/PFT/PC 变量在数据浏览中标识维度，首版不给错误的折线图。
- 指标至少包含 n、RMSE、MAE、Bias、R²、Pearson r、NSE、KGE、KGE r/α/β 分量、模型/观测均值和标准差。
- 多站点比较提供变量/指标切换、搜索、排序、排名条和完整失败原因。
- 诊断提供时间覆盖、缺测、物理范围、能量平衡残差；所需变量缺失时显示“无法计算”及缺项。
- 导出覆盖 CSV、JSON、Markdown、HTML；图表提供 PNG 快照入口。

## 5. 验收标准

1. 同时跑完 4 个站点后，总览显示 4 个独立站点，均能切换曲线和日志。
2. 结果站点切换不改变参数页批量编辑目标。
3. 旧算例、残留勾选和算例改名不会改变本次结果范围或观测匹配。
4. 一个站点缺观测时，其余站点评估继续完成并保留结果。
5. 90 个站点的批量评估并发数不超过配置上限，UI 可报告进度并取消未开始任务。
6. 长序列显示请求有点数上限，极值不因降采样丢失。
7. 图表缩放、窗口调整、中英文和深浅主题均正常，结果页没有横向溢出。
8. 导出内容包含分析范围、设置、指标、失败原因、版本与版权署名。

## 6. 验证顺序

1. 纯 JS 数据模型测试：范围、并发、缓存、降采样、CSV。
2. Rust 指标和 history catalog/series 测试。
3. 静态 GUI 接口检查与七分栏 DOM 测试。
4. Tauri 后端测试、clippy、fmt。
5. Chromium 交互与截图检查。
6. 真实 4 站点结果浏览、评估、诊断和导出。

## 7. 实施补充

- 批量评估调用 `metrics --summary-only`，单站点摘要约 2.2 KB；点击某个变量后才通过 `--pairs-var` 读取该变量最多 2400 个保极值配对点。
- history 的多个变量按月度文件成组读取，每个文件只打开一次；观测文件也只打开一次。
- 模型—观测时间匹配由逐样本线性搜索改为有序时间轴二分定位，保持原有 1 秒容差。
- 实测 AT-Neu 11 年评估由不可接受的二次复杂度降至约 1.2 秒；AT-Neu、AU-Cpr、AU-DaP、AU-DaS 四站并发摘要约 0.61 秒完成。
- AU-Preston 实际 history 索引为 16 个文件、22771 步、146 个变量，其中 129 条时间序列、11 个垂直剖面、4 个分类维度和 2 个标量；多维变量只分类展示，不错误压成一维曲线。
