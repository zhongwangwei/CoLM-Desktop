# 前处理：用自己的数据生成可跑的模型输入（设计）

> 这是**设计**，不是实施计划。计划另出，且按阶段拆成三份。

**目标：** 让第 1 步「前处理」从占位页变成真功能 —— 用户拿自己的数据
（别的通量网络的 netCDF、或者 CSV/Excel 表格），在界面里生成 CoLM 能跑的
强迫场与站点属性。

**边界：** PLUMBER2 与 Urban-PLUMBER **继续直读**，不进转换管道。

---

## 0. 现有架构的两个事实（设计的出发点）

**一、`colm-forcing` 不转换数据，只描述数据。**

```rust
//! 把一个 PLUMBER2 强迫场文件翻译成 CoLM 的 `nl_colm_forcing`，并在开跑前校验。
//! **本 crate 不转换数据。** CoLM 直接读 PLUMBER2 的 Met 文件
```

**二、变量识别按槽位，不按名字。** `slots.rs` 定了 CoLM 的八个槽位
（`MOD_UserSpecifiedForcing.F90`：`1=T 2=q 3=psrf 4=precip 5=u 6=v 7=SW 8=LW`），
每个槽位有一组**候选名**，第一个在文件里出现的胜出：

| 槽 | PLUMBER2 | Urban-PLUMBER |
|---|---|---|
| 3 | `Psurf` | `PSurf`（大小写不同） |
| 4 | `Precip` | `Rainf` |
| 5 | *（无）* | `Wind_E` |
| 6 | `Wind`（标量） | `Wind_N` |

只有第 5 槽可以空 —— 标量风数据集没有它。

**所以「认第三套数据」在现有架构里本来就有位置。** 但用户要的比这大：
还要能处理单位不同、时间轴不同、以及根本不是 netCDF 的表格。

---

## 1. 架构：转换成标准格式，但只转认不出来的

```
用户数据（变量名不同的 netCDF / CSV / Excel）
      │
      ▼  前处理 · 强迫场子栏
  转换管道：读 → 映射到 8 个槽位 → 单位换算 → 时间轴归一 → 写出
      │
      ▼  产物目录（与源文件分开存放，**原始数据永不改动**）
  一份符合 PLUMBER2 约定的 netCDF
      │
      ▼  从这里起与内置数据集走同一条路
  colm-forcing 描述 → CoLM 直读 → 建算例 → 跑
```

**边界：认得出、且不需要合并的直读；需要合并或换算的转。**

| 数据 | 走哪条 | 为什么 |
|---|---|---|
| PLUMBER2（90 站） | **直读** | 变量名与单位都认得出，`Precip` 已经是总降水。转它只会多一份 50 MB 拷贝和一次误差机会，而黄金回归正靠它 |
| Urban-PLUMBER（21 站） | **转** | 它把降水分成 `Rainf` 与 `Snowf`，而槽位机制是「一个槽位一个变量名」——不合并就**丢掉全部降雪** |
| 用户自定义 | **转** | 名字、单位、时间轴都可能不同 |

**「不转」的真实理由不是「内置的就不动」，是「不必要的转换只会多一份拷贝
和一次误差机会」。** Urban-PLUMBER 的转换是**必要**的 —— 见下。

### 1.2 Urban-PLUMBER 现在丢掉了全部降雪

**实测**（21 个城市站，`Snowf` 占总降水的比例）：

| 站点 | 丢掉的比例 |
|---|---|
| FI-Kumpula / FI-Torni（赫尔辛基） | **24.7%** |
| US-Minneapolis1 / 2 | **16.5%** |
| PL-Lipowa / PL-Narutowicza（罗兹） | **14.9%** |
| CA-Sunset（温哥华） | 9.8% |
| US-Baltimore | 6.4% |
| JP/KR/UK/NL/FR/GR 六站 | 0.4–2.9% |
| AU-Preston、AU-SurreyHills、SG、MX、US-WestPhoenix | **0%** |

根因：`slots.rs` 第 4 槽的候选名是 `["Precip", "Rainf"]`，命中 `Rainf`
之后就不再看 `Snowf`。**高纬站现在少了四分之一的降水，而模型照样跑得完、
曲线照样好看** —— 正是这个项目反复在防的那类失败。

**PLUMBER2 不受影响**：实测 90 个站**全部**只有 `Precip`（总降水），
零个含 `Snowf`。所以这条只牵动那 21 个城市站，且它们没有黄金基准
（只有 CN-Cng 有），不涉及重录判据。

**AU-Preston 是 0%**（墨尔本，验收窗口在 1 月盛夏），所以刚立起来的那条
基准（264 条、`f_tref` 峰值 311.964998337472 K）**修完仍然成立** ——
它可以继续当对照锚点。

### 1.3 合并降水时**保留相态**，不要相加了事

CoLM 接收的是**总降水**（`forc_prc` 对流性 + `forc_prl` 大尺度），
然后自己判相态 —— `MOD_RainSnowTemp.F90` 的 `rain_snow_temp`，三种方案
（`DEF_precip_phase_discrimination_scheme` = I/II/III，默认 `I`），
判据是**湿球温度**（`CALL wetbulb(forc_t, forc_psrf, forc_q, t_precip)`）。

所以：

```
观测给的相态（Rainf / Snowf）   ← 实测的事实
CoLM 判出的相态（湿球温度方案）  ← 参数化的推断
```

**简单相加会把前者永久换成后者。** 对 FI-Kumpula 那种 24.7% 是雪的站点，
等于把「观测说这是雪」换成「模型猜这是不是雪」，而模型照样跑得完。

**做法**：合并进第 4 槽供 CoLM 用，**同时把 `Rainf` / `Snowf` 原样保留
在产物文件里**，并在合成变量的 `source` 属性里说明它是怎么来的：

```
Precip:source = "Rainf + Snowf, both kept in this file; CoLM re-derives phase
                 by wet-bulb temperature (MOD_RainSnowTemp.F90)"
```

三条理由：

1. **可追溯** —— 产物文件能自证「总降水是怎么来的」。不保留的话，
   读文件的人只看到一个 `Precip`，不知道它是原生的还是合成的
2. **可回退** —— 将来要对比「观测相态 vs 湿球温度方案」时数据还在。
   那是一个真问题：观测明说是雪而模型判成雨，雪的反照率与融化过程完全不同
3. **不丢信息是转换器的底线** —— 这条管道已经立了「原始数据永不改动」，
   产物这边也该守住「不丢原有信息」

**用户自己的数据同理**：若他给的也分了相态，一样合并 + 保留。
转换器不该假定「用户只有总降水」。

**为什么用户数据要转**（而不是也走「描述」）：用户的数据可能单位不同、
时间轴不均匀、缺变量需要推导 —— 这些是**真改了数值**的操作，
描述解决不了。而一旦要改数值，就必须写出新文件（原始数据不动）。

### 1.4 这个设计自带一个判据

转换器最难回答的问题是「转出来的对不对」。这里有个免费的对照组：

> **拿 CN-Cng 的原始 Met 文件走一遍转换管道，转出来的文件跑出的 history
> 应当与直读逐位相同。**

CN-Cng 是黄金回归站点，直读的结果有 `identical: 129 variables` 钉着。
转换器若引入任何误差 —— 单位换算、时间轴取整、精度损失、缺测填补 ——
这个对照立刻会露出来。

**没有这个对照，转换器的正确性只能靠肉眼看曲线。** 这条要写进验收，
而且要在写第一行转换代码之前先把它搭起来。

（前车之鉴：上一轮预抽土壤点值时，`serde_json` 默认浮点解析差 1 ULP，
三段照样跑通、曲线照样好看，是逐位比对把它抓出来的。）

## 2. 前处理分三个连续子栏

界面按**产物流向**组织，而不是把互不相关的工具堆在同一页：

```
① 前处理
   ├ 站点数据      身份/经纬度/模式/rawdata → <站点>_site.nc
   ├ 强迫场        源文件/变量映射/观测高度 → <站点>_Met.nc
   └ 就绪与交接    联合检查两份产物 → 基本设定 · 文件与目录
```

三个子栏共享同一个站点词干和产物状态。站点输入变化时，旧强迫场与旧就绪状态
同时失效；不能把不同站点的两份文件误配成一个算例。每一栏都必须说明
**缺什么、为什么不能继续**，不能静默跳过。

观测文件不再放在前处理：它不参与 `mksrfdata`、`mkinidata` 或 `colm`，只属于
结果页的模型评估与报告导出。这样没有观测的站点也不会被误认为前处理不完整。

### 2.1 站点数据子栏

**用户必填站点名称、经纬度；模式来自首页卡片。** 地类可选，rawdata 可选。
输出名固定为 `<站点>_site.nc`，避免生成后无法被站点扫描器识别。

`site::fill` 写出的 `REQUIRED_FIELDS` 12 项只是结构补齐，并不等于可以运行。
完整契约由 `site::audit` 按当前模式检查：

| 模式 | 必需内容 |
|---|---|
| IGBP / USGS | 相应地类、冠层高度、LAI/SAI 月气候态、24 项土壤水热变量 |
| PFT / PC | IGBP 地类、PFT/PC 比例与类型数组、分 PFT 冠层高度和 LAI/SAI、24 项土壤变量 |
| Urban | LCZ/城市密度、建筑与下垫面几何、树木 LAI/SAI、24 项土壤变量 |

生成结果只有三种状态：

| 状态 | 含义 |
|---|---|
| `self_contained` | 文件自身满足当前模式，可直接建例 |
| `ready_with_rawdata` | 文件缺项明确，但已选择 rawdata，运行时由全球数据补齐 |
| `blocked` | 缺少当前模式所需输入，也没有可用 rawdata |

**经纬度只能定位，不能生成真实科学变量。** 软件不得从坐标编造 LAI、SAI、
PFT 比例或土壤剖面。缺项要完整列在界面上；选择 rawdata 后也保留这张清单，
让用户知道哪些值来自外部栅格。

自然/城市身份写入 `colm_desktop_site_kind` 全局属性。旧文件没有该属性时，
只用城市专属变量判定；“没有 landtype”绝不能再被当成“这是城市站点”。

**每个写入值继续带 `source` 属性**，明确区分站点实测、全球栅格、CoLM 查表
和有依据的模块默认值。标称兜底只能服务结构补齐，不能被描述成站点实测。

### 2.2 强迫场子栏

**输入**：用户选择 netCDF，先探测变量，再确认八个 CoLM 强迫槽位。

| 步骤 | 判据 |
|---|---|
| 映射到 8 个槽位 | 先按 `slots.rs` 候选名自动识别；不认识的变量不猜 |
| 单位换算 | 转成 CoLM 期望单位，并把原单位和换算写入产物属性 |
| 时间轴 | 解析 `units`、检查均匀步长；不均匀时阻断而非擅自重采样 |
| 观测高度 | `height_v`、`height_t`、`height_q` 三项缺一不可，缺失时由用户补充 |

输出固定为与站点文件同词干的 `<站点>_Met.nc`，默认写入相邻 `Forcing/`
目录。转换成功后自动刷新站点扫描结果，不要求用户重新选目录。

变量映射必须在界面上可见。变量名猜错会产生“能跑完但结果错误”的静默失败，
其风险高于直接阻断。若源数据分别提供 `Rainf` / `Snowf`，产物应合成总降水供
CoLM 使用，同时保留原始相态变量和来源说明。

### 2.3 就绪与交接子栏

只有以下条件同时成立时才允许“用于基本设定”：

1. 站点状态为 `self_contained` 或 `ready_with_rawdata`；
2. `<站点>_site.nc` 与 `<站点>_Met.nc` 词干一致；
3. 强迫场探测、映射、单位、时间轴和三个高度均通过；
4. 产物路径仍然存在，且没有被后续输入修改作废。

交接一次性写入基本设定的站点目录、强迫场目录与 rawdata 目录，并跳转到
“基本设定 · 文件与目录”。这样前处理与建例共享同一份状态，不再靠用户重复输入。

## 3. 运行契约与交付边界

前处理的最小闭环不是“写出两个 netCDF”，而是“写出并验证能被当前模式消费的
两个 netCDF”。站点文件若仍依赖 rawdata，界面必须保留该依赖；建例命令也必须
把 rawdata 原样写入自然站点算例，不能只在城市模式传递。

当前交付支持 netCDF 强迫场。CSV/Excel 是后续输入适配器，不应改变站点审计、
标准产物命名或就绪交接协议。新增输入格式只需接到同一转换器前端。

## 4. 复用什么

| 已有组件 | 位置 | 职责 |
|---|---|---|
| 槽位表与解析 | `colm-forcing/src/slots.rs` | 八个槽位、候选名和插值算法 |
| 强迫场校验 | `colm-forcing/src/check.rs` | 必需变量、时间轴与覆盖窗口 |
| 站点结构补齐 | `colm-srfdata/src/site.rs` | 12 个结构字段的站点/栅格/默认来源 |
| 站点运行审计 | `colm-srfdata/src/site.rs` | 自然、PFT、PC、城市的完整变量契约 |
| 按格点读栅格 | `colm-srfdata/src/raster.rs` | `point_f64` / `point_i32` |
| 城市站预抽表 | `colm-srfdata/src/urban_soil.rs`、`urban_extra.rs` | 已验证城市站点值 |

扫描、`site-new`、`new` 和 GUI 必须复用同一个站点身份/就绪判据。若各自复制规则，
“界面显示可运行而建例失败”或“扫描认为自然、建例认为城市”的问题一定会重现。

## 5. 错误处理

- **认不出来的变量不猜**：界面上列出「文件里有哪些变量」与「哪个槽位还空着」，
  让用户指定。猜错的后果是跑得完而结果错，比报错严重得多
- **单位换算过的要标出来**：产物文件里带属性说明「原单位 X，换算成 Y」
- **时间轴不均匀就报出来**，不要自作主张重采样
- **产物与源文件分开存放**，原始数据永不改动

## 6. 不做什么

- **不转内置数据集**（黄金基准不动）
- **不做时间轴重采样**（前处理页原设计里的第 2 条，等遇到真需求再说）
- **不做栅格裁剪**（原设计第 4 条 —— 城市站已经用预抽表解决了，
  裁剪的收益要先量）
- **不引入前端框架或 npm 依赖**（既有硬约束）
- **不做批量转换**（先让一个站点走通）
