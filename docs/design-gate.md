# 进门向导：按约束顺序选完再进主界面

**目标**：进入六步主界面前，按上游到下游选定空间结构、次网格、
土壤水力、物理过程和调试开关。

## 0. 运行时边界

宏改造（`docs/plan-macro-runtime.md`）已把下列选择变成 namelist 开关：

| 组 | 运行时开关 |
|---|---|
| 调试 | `DEF_USE_CoLMDEBUG` / `RangeCheck` / `SrfdataDiag` |
| 土壤水力 | `DEF_USE_Campbell_SOIL_MODEL` |
| 示踪物 | `DEF_USE_TRACER` |
| LULC 系 | `DEF_USE_LCT` / `PFT` / `PC` + BGC/URBAN/LULCC |

PFT/PC 是运行时选择，PC 已用站点算例完成三阶段实跑。USGS 仍改变编译期
`N_land_classification` 及查表数组，因此与 IGBP 分别构建；界面按第 2 页选择自动匹配，
不再让用户手动选内核。CROP 仍置灰，直到它的编译期数组分歧被解决。

## 1. 页序

“研究什么过程 / 默认预设”页已删除，不保留隐式 profile 状态。

| 页 | 问什么 | 约束到下游的什么 |
|---|---|---|
| **1** | 空间结构（站点 / 区域 / 全球） | 当前只有站点步骤链可用 |
| **2** | 次网格（USGS / IGBP / PFT / PC） | BGC 要 PFT 或 PC；PFT/PC 改变站点数据要求 |
| **3** | 土壤水力（van Genuchten / Campbell） | TRACER 要 van Genuchten；土壤参数要求随之变化 |
| **4** | 物理过程（URBAN / LULCC / BGC / CROP / TRACER） | 被第 2、3 页的选择约束 |
| **5** | 调试（RangeCheck / CoLMDEBUG / SrfdataDiag） | 无下游约束，可全部不选 |

## 2. 交互约束

- 必选页未选时禁用“下一步”；调试页可空着完成。
- 所有选项都列出。不可用项置灰，同时写明“需要什么”和“哪页的什么选择造成”。
- USGS 只在安装中能找到 USGS 产物时可选；发行包必须同时携带 IGBP 与 USGS。
- BGC 被挡时可点提示返回第 2 页；TRACER 被挡时可返回第 3 页。
- 回退改上游只清掉已失效的下游值；土壤水力、其他物理开关等无关选择保留。
- 完成时将实际选择一次写入新算例的 `case.nml`；不写 profile 或预设名。

## 2c. 站点数据的要求随选择变，要当场说

选了 PFT/PC 之后，站点文件要提供 `pfttyp` / `pctpfts`
（`MOD_SingleSrfdata.F90` 的 `USE_SITE_pctpfts`），而 PLUMBER2 的
站点文件**没有这两个** —— 会回落到 `<rawdata>/plant_15s/` 全球栅格。

反过来，选了 Campbell 之后，`alpha_vgm` / `n_vgm` / `theta_r`
不再需要（`mksrfdata` 里它们是 VG-gated 的）—— **要求变松了**。

**这两条都要在选的当场说**，不能等用户走到第 3 步扫站点目录时
才发现数据用不了。这正是「上一层定好、下一层缩紧」在数据这一侧的
体现：**选择不只缩紧后面的选项，也缩紧对输入数据的要求**。

## 2d. 向导的选择怎么贯穿后续全流程

**可以，而且这正是向导的价值** —— 但要先分清哪些数据受它影响。

### 一个关键区分：强迫场无关，站点数据有关

| | 受向导选择影响吗 | 为什么 |
|---|---|---|
| **强迫场** | ❌ 无关 | 八个槽位（气温/比湿/气压/降水/风×2/短波/长波）是固定的，不随 LULC 或物理方案变 |
| **站点数据** | ✅ 有关 | `IGBP_classification` / `USGS_classification` / `pfttyp`+`pctpfts` 三选一，看次网格方案；VG 那几个参数看土壤水力 |

**所以强迫场转一次到处能用，站点文件得跟着配置走。**

这条对用户体验有直接影响：他改了向导的选择重新进来，
**前处理页的强迫场产物仍然有效**（不必重转），但**站点文件可能要重建**。
界面上要说清楚这个区别，别让人以为改了配置就要从头再来一遍。

### 三层衔接，各管一段

```
向导        →  写入 case.nml 的 DEF_USE_*
参数页      →  不重复显示，也不让预设覆盖
运行时检查  →  兜底，外部手改配错时直接 CoLM_stop 并说明
```

向导字段是本次批量算例的上游约束，参数页不再列出第二份开关；参数预设保存和
套用时也跳过这些字段。需要另一套次网格、土壤、物理或调试组合时，重新走一次
向导建一批算例。运行时检查仍保留，防止外部手改 `case.nml` 后静默跑错。

### 参数页的字段过滤要跟着改

参数页现在按内核的 `macros` 过滤：

```js
k.title = `本内核未编入（需要 ${meta?.requires?.join('、')}），设了也没用`
```

**宏消失之后这套失效** —— 第三组已经踩过（`xtask/src/usage.rs` 的
`SUBSYSTEMS` 映射让 `DEF_TRACER_*` 全被标成「本内核未编入」，
而实际上它们现在**永远可用**）。

改成按**运行时选择**过滤，措辞也要跟着变：

```
旧：本内核未编入（需要 BGC），设了也没用
新：当前配置下不生效（需要 PFT 或 PC 次网格方案）
```

**区别不只是措辞** —— 旧的意思是「你得重编内核」，新的意思是
「你改个开关就行」。那正是这次宏改造带来的变化。

### 多个算例共享一次向导

第 3 步可以一次建多个算例（批量）。**它们共享同一次向导的选择** ——
向导问的是「这次要跑什么」，不是「这个算例要跑什么」。

要给不同算例配不同物理方案的话，那是**跑两次**的事，
不是在一次向导里表达的事。

## 3. 边界

- 不记住上次选择；向导问的是“这次跑什么”。
- 不在向导或主页里手动选内核目录；运行产物由次网格选择自动匹配。
- 不在本改动中实现区域/全球步骤链；它们在第 1 页保持置灰。
