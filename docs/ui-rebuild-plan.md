## 1. 为什么重做

五步条、启动页、单独的运行方式页一路加下来，界面越来越多、越来越复杂，始终没有一条简单的使用流程。更深的原因在概念上：参数、物理开关、AI 网络写在算例里，和"版本"分开，同一个算例换了参数以后，说不清结果是哪套模型算出来的。

## 2. 原则

1. **版本 = 模型怎么算**：源代码、物理过程开关、参数值、AI 网络。改其中任何一样都产生新版本。官方版只读。版本用过之后再改，记成新的修订，不覆盖旧的。版本之间按来源成树。
2. **算例 = 算哪里、算什么时候**：站点或区域、时段、强迫场、地表数据、初始场与预热、观测、输出。算例里不再放参数和物理开关。
3. **一次运行 = 版本（含修订）× 算例 × 机器**，三样都写进出处。
4. **从选版本开始**：没有顶栏、没有步骤条、没有启动页、没有单独的运行方式页。
5. **常见情况由软件决定**：只在用户想偏离默认时才出现选项，放在"高级"折叠里。
6. **软件做过的每件事都进同一本历史台账**：左栏独立入口，可以筛选、追溯、重现。

## 3. 用户流程

```
选版本（官方版 / 已有版本 / + 新建修改版）
  → 选站点或打开算例（其余自动填）
  → 运行（默认本机，可换服务器）
  → 看结果（修改版自动和来源版本对比）
  → 想更好：调参数 / AI 替代 / 改物理开关 / 改代码 → 产出新版本 → 回到"看结果"
任何一步事后都能在"历史记录"里查到
```

## 4. 后端改动

| 改什么 | 现在 | 改成 |
|---|---|---|
| 版本的内容 | 只有源代码（工作区） | 代码 + 覆盖层（参数、物理开关、AI 网络）；记来源版本和修订号 |
| 参数与物理开关 | 算例的 `case.nml` | 版本的覆盖层；算例只留数据和时段 |
| AI 网络 | 装进算例的 `hybrid.toml` | 装进版本 |
| 运行 | `run --model-version` 只换程序 | 再把覆盖层叠到算例的运行副本上（原算例不动）；出处记版本和修订号 |
| 率定、AI 学习的结果 | 另存成新算例（`study-apply`） | 最优那组存成新版本，自动命名，注明在哪个算例、哪段时间得出 |
| 只改参数、开关或网络的版本 | — | 不编译，几秒建好，沿用来源版本的程序（本机和服务器都一样） |
| 服务器运行 | 上传算例和版本代码 | 覆盖层随版本一起上传；只改覆盖层的版本复用来源版本的引擎快照 |
| 历史 | 分散在 `runs.jsonl`、`produced-by.json`、远程作业记录、研究状态、编译门禁 | 一本集中的台账（第 5 节） |
| 已有数据 | — | 一次性迁移：已有算例里的参数改动和网络生成对应版本，算例里去掉这些；自动进行，不问用户 |

不用改：编译与就绪检查、出处文件格式（只加字段）、远程作业与引擎租约、研究的计算引擎、比较两个版本、引擎清理。这些路径只需要多写一条历史记录。

## 5. 历史记录

**存储**：应用数据目录下一个只追加的 SQLite 台账。动作开始时写一条，结束时补全状态；没补全的显示"未结束（可能中断）"。大的内容（日志、清单、指纹表）不复制，只存指向原文件的路径。首次启动时把已有的出处、远程作业记录、研究状态、编译门禁导入。不记密码、密钥、令牌，只记登录方式。

**类型**：运行、编译、检查、研究、版本（新建/修订）、算例（新建/修改）、服务器（测试、引擎清单、清理、解除中断）、取回、助手（助手做出的改动）。

**列表**：按天分组。每行：时间 · 类型 · 对象（算例 × 版本）· 机器 · 状态 · 用时。搜索（算例、版本、作业号、路径）；按类型、机器、版本、算例、时间筛选；导出为表格。

**详情**：

- 标题区：类型、结果和退出码、开始与结束时间、用时、由谁发起（你 / 助手 / 研究）。
- 关联：同一件事的前后几条（如 查看引擎清单 → 运行 → 取回），这个算例的上一次运行。
- 对象：算例和路径、版本和修订号、参数覆盖情况、时段。
- 机器：本机记主机名、系统、CPU；服务器记主机、登录方式、根目录、调度系统、作业号。
- 程序：引擎、引擎快照、内核、线程。
- 输入：强迫场、地表数据、服务器上的算例副本，每个输入记 SHA-256。
- 输出：取回位置、文件、出处文件。
- 完整命令（可复制重现）、日志末尾几行和完整日志链接。
- 操作：用同样设置再跑、和另一条对比、打开文件夹、导出这条记录。

算例页的"运行记录"、版本页的"用到它的运行"都是这本台账的筛选视图，不另存。

## 6. 前端改动

新做一套（React + TypeScript + Tailwind + shadcn/ui，图表用 uPlot），旧界面保留到切换为止。

**去掉**：顶栏上下文条；编号步骤条；启动页的"选择运行方式"和"这次要跑什么"；"运行方式"页；运行面板里的版本选择；新建算例时的"物理预设"。

**新做或改做**：

1. **第一屏：选版本**。按来源显示成树，写着每个版本的目的和状态。"+ 新建修改版"只问名字和目的，再选怎么改（参数 / 物理开关 / AI 网络 / 代码）。
2. **选算例**：示例站点、用我的数据、打开已有算例。新建只问站点（或区域）和名字。
3. **算例页**：设置（数据、时段、输出）· 运行记录 · 结果。
4. **运行按钮**：默认本机；旁边的箭头换到服务器；"高级"里放引擎、线程、只跑某一段。
5. **结果**：修改版默认和来源版本对比；调参数和 AI 的产出直接是新版本。
6. **版本页**：代码 · 参数 · 物理 · 网络四块，加修订历史和"用到它的运行"。
7. **研究**：结束时一个按钮"存为版本"。（已改：研究结果先写进草稿，在版本页审阅、冻结；写回前与默认参数比较，见 `docs/uncertainty-and-tuning.md`。）
8. **计算资源**：按示意稿；引擎快照、中断的提交记录收进"维护"。
9. **历史记录**：第 5 节的列表和详情。
10. **左栏**：顶部"当前版本 · 换版本"、新建算例、算例列表；下面是版本库 · 计算资源 · 历史记录；底部常规/专家切换、AI 助手、帮助。
11. **专家模式**：只把各处"高级"默认展开，不另做页面。
12. **AI 助手**：右侧面板，看得到当前版本、算例和所在页面。

## 7. 顺序

1. 示意稿定稿（第 9 节未完成的部分），确认后再写代码。
2. 后端版本覆盖层：叠加运行、修订、出处、只改覆盖层不编译、迁移，加测试。
3. 历史台账：存储、导入已有记录、各条路径写入。要在新前端之前，因为运行记录和版本页都读它。
4. 新前端主线：选版本 → 选算例 → 运行 → 看结果。
5. 改进的循环：调参数和 AI 存成版本、改代码、和来源版本比较。
6. 服务器、计算资源、专家模式、历史记录页；然后切换到新界面，旧界面下线。

## 10. 用户采纳的评审修订（2026-10-12，实施依据）

- 官方版默认选中，左栏可换版本；不增加必经版本选择页。主操作仍能直接新建、打开或试示例。
- 模型编辑保留草稿；保存或运行时冻结不可变修订。记录覆盖参数的地类/过程适用性和率定/验证站点时段。
- 免编译限于兼容已有程序和内核的运行时覆盖。编译期开关匹配适用内核；AI 网络仅支持 Rust。来源程序解析、就绪检查、远程快照引用及清理保护必须适配。
- 自动迁移保留原算例、原配置和网络；导出独立模型版本与算例数据描述。迁移可重试、可回退，不原地删掉旧 case.nml 的字段，不虚构被覆盖的历史配置。
- 运行只物化版本修订与算例数据的副本；记录有效配置、程序、内核、输入/输出内容身份和运行 ID。相同修订不因用户后来编辑而变化。
- 有同输入/时段/评估条件的真实来源结果才自动对比；缺基准明确提示，不自动追加计算。
- 历史记录有科学/操作意义的动作和状态；开始/结束追加事件，按稳定 ID 导入去重。中断记录先核对真实进程/远程作业，不自动重跑不确定提交。
- 新前端采用 React + TypeScript + Tailwind + shadcn/ui（Radix），沿用 uPlot 和既有科学/远程算法；旧界面只在迁移期间保留，新主线通过完整验收后切换。
- 助手的可见页面、字段、动作、等待、审批、错误及上下文契约随 React 同步迁移；不能只替换面板外观。
- 按用户新指示连续完成实现，末尾集中进行回归、接口/类型/静态检查、原生构建、真实任务与视觉验收；发现问题继续修复。
- 原有 main 合并授权门仍保留：未获用户明确许可不合并、不推送 main。

私有示意稿暂不可访问，按本文界面结构与已有本地设计参考、青绿/深蓝主题实现；这一缺口不阻塞已授权实现。
